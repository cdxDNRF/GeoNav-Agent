# 目录结构与维护

长期约束统一见[AGENTS](../AGENTS.md)，当前事实见[PROJECT_STATE](../docs/PROJECT_STATE.md)。根[README目录登记](../README.md#目录用途与登记)继续作为新目录创建前的登记入口；本文件提供维护说明，不复制实时研究状态。

```text
大数据工程/
├─ AGENTS.md                      长期规则
├─ README.md                      总览、导航与目录登记
├─ .agents/
│  ├─ TASKS.md                     任务认领及写入范围

│  ├─ 本地/                        提示/外部助手记录，仅本地
│  └─ 归档/                        整理前文本、规则对应及核验
├─ docs/PROJECT_STATE.md           当前状态唯一维护入口
├─ project/{src,defaults}/         代码与按协议配置
├─ DATA/{raw_data,processed_data}/ 原始及派生数据，保持原址
├─ models/                        保留预训练权重

```

`workflows/`尚未启用，本次不创建。新协调目录采用用户指定名称，其它非代码新目录仍优先中文。

## 按变更类型更新

| 变更 | 应更新的可维护文件 | 保留的原件 |
|---|---|---|
| 认领/释放任务 | `.agents/TASKS.md`自己的记录 | 其它执行者记录 |
| 完成或中断任务 | `.agents/HANDOFF.md`新增交接 | 已有历史交接 |
| 阶段结论变化 | `docs/PROJECT_STATE.md`及对应实验索引 | 批次原报告、方案、判定与源码 |
| 新目录用途 | 根README，必要时补本文 | 已有目录/数据位置 |
| 新协议默认 | 新版本配置/注册表及PROJECT_STATE | 原M0、旧验收及旧默认版本 |
| 新材料或图表 | 新版本、来源/图注、对应材料索引 | 用户填写文档与已封存图/报告 |

不要重新向README追加整段历史实验日志，也不要在旧“当前进度”建立第二份状态。旧封存整理/收尾脚本可能仍假设旧README结构，不能为兼容它们还原或覆盖当前入口；新收尾任务按现有结构另立版本。

## 原件、复现与恢复

各批模型、任务、原图/特征、源码快照与哈希共同构成证据，不能只拿汇总表重跑。历史目录细项保存在[历史开发记录](历史开发记录.md)、[71批索引](实验索引.md)和[本次整理前原样文本](../.agents/归档/README.md)。原始数据、权重、模型、代码及实验原件没有因本次文档拆分迁移。

旧恢复备份见[整理记录](整理记录_2026-10-02_v1/)：其中删除文件/重复副本ZIP与修订前报告仅按原相对路径恢复所需单项并核对哈希，不整包覆盖工作区。最新用户稿不得被旧`build_report.js`、`build_midterm_report.py`或封存材料脚本覆盖；材料更新先检查输出并另登记版本。

凭据与`.env*`不进入源码、报告、快照、共享包。Git提交范围按当次授权审查，已有用户修改及历史失败结果保留；不要依据旧README里的提交号判断当前仓库。
