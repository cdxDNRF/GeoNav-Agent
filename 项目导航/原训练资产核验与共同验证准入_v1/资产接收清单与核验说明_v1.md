# 资产接收清单与核验说明 v1

本清单是BENCH-021的固定准入规则，**不是“资产已到位”声明**。缺项见[机器清单](元数据/资产准入清单_v1.json)。建议作者提供一个小型manifest包，先明确以下关系，再决定是否另批下载大型资产。

1. `source_split`：dataset版本/许可，原文件ID与SHA，train/val/test清单及足迹。需能还原img_i对应哪个源图，核验地理交叉；不能仅给832/178/179等数量。
2. `encoder_recipe`：checkpoint实际使用的编码器repo/revision/文件SHA，视觉模型类别、输出字段与维度、RGB/裁切/缩放/归一化，投影与L2操作、转换源码/参数。默认示例不能当作原训练run绑定。
3. `feature_bank`：训练/验证/测试bank的SHA、shape/dtype/字节/entry数，source_id→row和patch_index→物理格映射、顺序和裁切规则；原bank缺失时必须给可验证重建方法及参考输出，再在另批获授权后做数值检验。
4. `training_run`：run_id/代码提交/完整配置/种子、实际预训练与PPO更新/停止量、优化器/奖励/资源与环境、选择验证规则、原日志或其SHA。812步snapshot不是PPO步数，也不是完整run终点。
5. `checkpoint_run_map`：每个发布权重的SHA→run_id→split/encoder/bank的明确对应，PPO是否从这份pretrain继续，论文表对应哪个checkpoint。
6. `paper_evaluation_map`：原固定任务清单及SHA、数据/模态/距离/网格/预算/动作/停止/成功/SG定义、论文表/行与评测源码提交；区别原生论文评测与本项目4动作适配协议。

每项采用两层审查：文件大小/SHA/shape/身份等客观核验；再核查权威材料是否确实支持跨资产关系。后者需保存authority_url、原文出处与简短quotation、原件SHA、reviewer及审阅记录。两个未建立关系的文件各自SHA正确仍不够。公开来源称谓只能证明发布位置，不能自动证明论文run身份。

准入检查：`D:\PYTHON\python.exe -B project/src/eval/audit_original_training_assets_v1.py check <新清单路径>`。只读、不载入模型；返回缺项和formal_execution_allowed。检查不认证作者、不读取全部bank张量、不证明目标作用。不要覆盖本批已封存机器清单；新资产另登记新批次/目录/收据/使用权限。

资产齐备也只是工程前提。BENCH-019的失败结论继续有效；若实际表征相同，则不能以“资料补齐”重新跑相同候选。若存在明确差异，新开发验证还须真实目标对移除/错误目标各≥5个百分点、来源组CI下界>0、SG及恢复/损伤同步报告和全部工程核验通过，才考虑新来源共同确认。
