# 多 Agent 专项综合与反证

日期：2026-10-01。用途：衔接任务书、研究计划、状态勘误及来源卡的反证草稿；不覆盖旧综述，不新增实测。形成于11d到齐前；主Agent交付版已经整合11d与15引用核验，最终结论/协议以12专项报告和14冻结设计为准。限定同一导航执行体的决策机制，不把多UAV并行当作同一问题。论文结果均为作者报告，以下迁移判断是待检验假设。

## 一页决策建议

**决定：保留一项小而可证伪的协作候选，不扩成常驻多 Agent；有条件保留第二项。** 当前 Edge 是有训练组件的强模块系统：S2、S3、SwissView 已通过；SwissView 是同模态新源文件迁移，不等于严格地理不重叠或异时目标泛化。[本地状态勘误](D:/桌面/XDUCS-courses/大四/大数据工程/调研/16_原综述状态勘误与本地证据_v1.md) 旧 20 题验证为四种方案 SR 均 95%、45 次导航请求全弃权/零动作变化；只有 3 道原成功题触发，唯一失败题未触发。双 Agent 60 条记录无二次触发，交换消息没有下一调用消费。因此它没有测到失败修复或跨轮纠正；相同分数也不是等价证明。[本地状态勘误](D:/桌面/XDUCS-courses/大四/大数据工程/调研/16_原综述状态勘误与本地证据_v1.md)

**第一候选（优先）：**公开状态上的覆盖/预算停滞事件，二调用 evidence-ledger E → coverage/waypoint planner P。E 仅整理已访问图像与轨迹的证据来源、反证及已否定假设；P 必须在同一事件中接收并消费 E 的消息，提出合法下一 waypoint/动作及新增覆盖理由。分别标记“目标证据”（支持/反对目标）和“探索/利用证据”（哪些已看位置、路线是否重复、还剩多少预算）。缺少目标支持不能成为禁止探索动作的门槛。两调用若不改变动作或消息不影响 P 输出，机制即未成立。

先用已有轨迹做**离线合法状态机会覆盖诊断**，看公开字段能否形成可执行且非 oracle 的 trigger；这不是新评测、不重放出新成绩，也不能从事后邻接标签推断在线可识别率。通过后再冻结同一 trigger 与同一结构化记忆，比较 E→P 双角色和单 Agent 同记忆工具流水线；另有同调用安排的单 Agent 反思基线。若同一模型、相同可见输入的单 Agent 工具链可精确模拟 E→P，则任何效果只能归因于状态组织/提示/调用流程，不能宣称“Agent 数”因果收益。

**第二候选（条件保留、不得并行堆臂）：**planner 先独立提出计划，blind counterevidence critic 后独立读公开状态并指出可复核的反证，planner 单轮修正；共三次调用，和相同三调用/调用时序的单 Agent 反思比较。先验证 critic 有基于已访问视觉/证据的能力；若只是文本复述、没有图像/可追溯来源判断能力，停止，不把“critic”标签当视觉核验。

**此刻不建议：**大批云端调用、多 UAV 扩张或重复 cue 投票。论文中协作收益随任务可分解性改变，顺序规划任务会明显退化；室内全景、语言路线、RGB-D/pose 与本项目的局部航拍目标搜索差别大，数字不迁移。[B01/A06 agent scaling](https://arxiv.org/abs/2512.08296) [A01 DiscussNav](https://arxiv.org/abs/2309.11382) [C08 SpaceVLN](https://arxiv.org/abs/2606.08992) 主线优先级仍应比较真实覆盖扩大、异时目标和跨步表征。真实 trigger 的代码接口/合法状态字段没有在本稿核验，不得写成现成规则或已实现功能。

## 五个领域综合（Ready 5）

### 1. 可协作的失败机制与任务可分解性

已有失败更常见于没能走到目标邻接处，而不是到了邻接处缺一次视觉表决。离线诊断在 10×10 的 343 个失败中记到 11 次行动前真实邻接机会，SwissView 的 198 个失败中记到 1 次；这是 post-hoc evaluator-only 机会统计，不是可修复数、在线覆盖率或因果上界。[本地状态勘误](D:/桌面/XDUCS-courses/大四/大数据工程/调研/16_原综述状态勘误与本地证据_v1.md) 因而第一缺口是覆盖/预算与子目标组织。MapGPT 将已观测节点、连接和待达子目标维护在单 Agent 状态中，支持记忆/waypoint 作为机制候选，但其室内路线与航拍 patch 不是同一任务。[C03 MapGPT](https://aclanthology.org/2024.acl-long.529/)

分工只有在角色掌握不同的可追溯状态、产生有用新假设，或受约束地检查反证时才有可辨认机制。CA-VLN 是训练出的知识/历史模块流水线，不证明复制提示角色的收益；DiscussNav 的专家讨论按步增加采样/调用且视野权限更广；ReflectVLN确有后续调用消费反馈。独立核验已确认其在线C由执行模型预测，但训练反思/恢复使用GT参考轨迹与特权专家。因此只能借鉴接口，不能将其训练监督当合法在线字段。[A05 CA-VLN](https://www.mdpi.com/1424-8220/26/4/1254) [A01 DiscussNav](https://arxiv.org/abs/2309.11382) [A02 ReflectVLN](https://arxiv.org/html/2607.12680)。

### 2. 失败前可合法触发什么

在线 trigger 只可依赖目标图、当前/已访问图像及来源、位置、visited、合法动作、公开提议、原始 cue 分数和剩余预算；不得看真实目标位置/距离、未来成功、失败标签或未访问图像。[本地状态勘误](D:/桌面/XDUCS-courses/大四/大数据工程/调研/16_原综述状态勘误与本地证据_v1.md) 候选是短窗重复状态/路线、连续无新增覆盖或证据、预算风险、已观测证据冲突。原始 cue 分数不能称校准概率；已接受强 cue 可能正确也可能误接收，VLM 的 unknown 不应自动否决它。

Horvitz 的有限资源计算价值给出规范：只有额外推理预计值得其 token、时延和消耗剩余行动机会的成本才调用；Learning When to Plan 的论文中固定频率过低/过高均可能有损，且动态门控经过监督/强化训练，不能推成 prompt 自然学会 trigger。[C01 有限资源计算价值](https://www.erichorvitz.com/reflect.htm) [C04 Learning When to Plan](https://arxiv.org/abs/2509.03581) 本项目 trigger 仍是假设，阈值只能在开发源图上预登记，且应先由既有合法状态做离线覆盖诊断。

### 3. 角色、消息和实际动作影响

首选窄接口为 E→P：E 记录 `evidence_id / source_image / observed_at / supports_target / contradicts_target / coverage_state`；P 将输入证据转成候选合法 waypoint 和理由。这里 “支持/反对目标” 与 “覆盖/利用计划” 两种证据不可混并。Planner 要在日志中标注读取了哪些 evidence_id、其前后建议和最终动作；若同事件内没有 P 调用，就不能算跨步协作。MAST 的失效分类特别适合作逐条审计忽略输入、丢失上下文、重复步骤、reasoning-action mismatch 和验证不足，但其通用 Agent 轨迹不是本项目导航失败率估计。[B03/C07 MAST](https://proceedings.neurips.cc/paper_files/paper/2025/hash/b1041e52d3be19f0a9bc491657488e4a-Abstract-Datasets_and_Benchmarks_Track.html)

第二候选的critic独立读合法状态和公共候选，不看本轮草案；第三调用由planner读取草案和critic反证后修正。其输出限于来源ID与可验证约束，不允许看隐藏区域。TEACh仅文字计划Judge不能支撑视觉critic；VeGAS有效verifier经专门训练，并有同调用数Self-Consistency消融，未提供与单体reflection全面等实际总tokens证据。[A03计划核验](https://arxiv.org/abs/2509.02761) [A04 VeGAS](https://arxiv.org/abs/2605.12620)。

### 4. 公平对照、指标与可识别性

对照至少包含：强 Edge + 同结构化记忆的单 Agent 工具流水线；单 Agent 固定时点/事件反思（按调用安排匹配）；E→P 多角色。第二候选若启动，另用严格三调用单 Agent 反思匹配。固定模型、图像权限、合法动作、每题最大环境动作和 API call schedule；逐题报告实际 input/output tokens、图片、调用、时延，并画 cost–performance 曲线。call cap 不等于实际 token 相等；固定时钟/调用安排是敏感性控制，不能靠事后挑 token 数匹配或 padding 烧 token。等观察权限也不等后续地点相同：动作一变，未来可见路线图/图像就变；相同历史的 paired replay 只能评同状态动作纠正，不能冒充端到端 SR。

先分两类统计：预先规定的**全体任务队列**报告 SR/SG/Q；源图配对、按 source 与距离层事先抽样，失败诊断队列只报告 trigger 覆盖、动作变化、基线失败修复、基线成功损伤和机制链条。不得只从失败题挑样估总体 SR；已见源图用于开发，不能再包装成新 held-out。推断单位以源图为主，同图路线及 API 重复嵌套。报告源图层级的不确定区间、修复与损伤数，不把零差异说成等价。项目此前“+2pp 且 2/3 重复正收益”是内部扩展门槛，不是论文通用标准；95% 基线仅留 5pp 上行空间，损伤风险值得计入，但门槛不能替代 SR 估计与区间。Q 维持既有工程正常完成口径、接口解析率单列，不能用工程 Q 取代 SR。[本地状态勘误](D:/桌面/XDUCS-courses/大四/大数据工程/调研/16_原综述状态勘误与本地证据_v1.md) [B05 同预算推理策略](https://aclanthology.org/2024.emnlp-main.1112/) [B08 等 thinking-token 比较](https://arxiv.org/abs/2604.02460)

### 5. 与主线扩展的优先级

先检验实际覆盖与预算是否可被合法状态 trigger 识别，再谈角色是否有效。若多数失败始终没有邻接 cue，提升 cue verifier 的收益天然受机会限制；但“覆盖停滞”能否领先于失败可观测仍需数据验证。主线的真实地图面积、连续/异时目标、跨视角和长期位置/证据表征能检验更基础泛化问题；10×10 是同覆盖切图密度扩展，SwissView 是同模态迁移，不应将其宣传为真实地理扩张或全域迁移。[本地状态勘误](D:/桌面/XDUCS-courses/大四/大数据工程/调研/16_原综述状态勘误与本地证据_v1.md)

多 UAV 文献的单机与多机任务量并不总是同样本或同总步数。若以后研究多平台，须固定 fleet 总动作预算，并报告通信、并行时间及重复覆盖；这与本轮同执行体决策 Agent 是另一研究问题。[C09 GoalSwarm](https://arxiv.org/abs/2603.12908) 现阶段不要加大云端调用量或铺多机实验来扩大数字。

## Red-team：实验前必须能回答

1. **新信息在哪里？** 同一个 LLM、同一张已看图、同一份轨迹的两个上下文可以由单体 tool pipeline 仿真。若无信息增量、独立证据来源或可单独删除的消息作用，只能称工作流分解，不能称 Agent 数的因果收益。
2. **Trigger 可见且有用吗？** 用合法公开字段在全体既有状态离线算覆盖与预算风险；禁止用 11/343、1/198 的真实邻接或失败标签作在线门控。该诊断能淘汰明显无覆盖规则，不能证明动作改变后的反事实成败。
3. **是否把多个改动捆成一臂？** Trigger、memory、roles、仲裁、阈值一次全变会使归因不可识别。顺序应是既有 trace 诊断机会覆盖 → 冻结 trigger/记忆/接口 → 单体同记忆工具基线与多角色对照；再单独加 critic 或改变 trigger。
4. **信息权限是否被“同权限”掩盖？** 同样允许看当前与历史图，不保证两臂未来看到相同地点。端到端采用配对相同 source/task；动作同历史回放只诊断局部决策。不得把两种估计混成一个因果主张。
5. **成本及样本是否被挑选？** call 上限不是实际 token 配平；不要事后找相同 token 子集、用空话填满预算或把少数失败诊断样本当总体。冻结调用日程、报实耗曲线，开发源与 held-out 分离，所有臂覆盖全体预登记任务。
6. **成功基线掩盖了什么？** SR=95%意味着最多仍有5pp绝对修复空间，但有限题数下修复/损伤会很少；零损伤不等于安全，SR 相同也不等效。预登记可接受的损伤上限和区间解释，不沿用 +2pp/2-of-3 作为普适显著标准。
7. **论文新颖性在哪？** 同状态 E→P、公开覆盖 trigger 和消息消费可能是工程整合。只有相对强单体同记忆、同调用的可重复增益，并排除输入权限与后续观察路径差异，才有资格提出机制贡献；否则如实作为工程诊断或负结果，不以 Agent 标签包装新颖性。

**停止条件：** 离线 trigger 覆盖不到足够公开状态；P 不消费 E 消息；单体同记忆同调用追平；可恢复失败过少以致区间无法排除伤害；或 SR 提升来自多看地点/多动作而非角色机制。任一项成立即可收束协作支线，转向覆盖/目标变化/表征主线。11a/11b/11c 文献定位、版本与限制见对应来源卡；本稿不把其未核验的界面接口写作事实。
