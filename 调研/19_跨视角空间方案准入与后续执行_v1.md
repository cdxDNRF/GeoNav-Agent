# CV-027：跨视角空间方案准入与下一批工程条件

2026-10-23。有界的任务/资产核查，非穷尽综述，非新实验结果。本轮只新增既有目录内小型文件；0原图、模型加载/forward、训练、导航、模型API、权重/数据取得或6确认消费。平台4.11源码、航拍M0及历史验收不改。

**决策：没有已获准直接接入自主导航的新模型。唯一推进路线是OpenCVL少量成对素材的空间监督预检；这不是把整个数据集下载下来，也不是立即训练。**

## 1. 真正需要补的能力

任务保持“给定地面目标照片→只看当前航拍及合法历史→选择四方向→首次到目标格”。现有MM-GAG成功标签是数据配对中心代理格，尚未独立证明是精确拍摄点或可见地标。不能为适配某个模型悄悄换标签。CV-026已表明，当前原始余弦不能稳定充当接近方向；不再调阈值或重开旧局部梯度因素。[本地诊断](../DATA/processed_data/MM-GAG/连续观测空间证据诊断_v1/README.md)

许多被动跨视角方法处理“地面相机在给定航片的什么位置”，并不直接解决“目标还在当前航片之外时往哪走”。CCVPE明确以覆盖相机局部区域的航片作为参考，官方实现将热图归一化到该图内部。[论文](https://arxiv.org/html/2303.05915v3)、[固定源码](https://github.com/tudelft-iv/CCVPE/blob/3028aa5c1585d3c274c3a531bdce19846c9c3bd2/models.py#L319-L320)

据此作出的本项目推论：片内最高热图值不能单独当“目标在当前图中”的置信度，更不能当目标在窗外的方位。在当前首次到达自动成功的协议下，如果某模块只在进入正确格后才能判断位置，它也不能据此证明提高到达SR。将未访问整幅航片交给这种模块会改变输入权限，不能包装成原协议下的主动导航。

## 3. 为什么选OpenCVL做监督工程，而非立即换模型

OpenCVL包含普通街景照片，并区分较准的ZOD来源和有噪声的众包来源。原文说明参考航片为100m×100m、北向对齐，相机偏移并非固定零；SDK给出了像素坐标的轴向约定。[论文§3](https://arxiv.org/html/2608.25274v1)、[固定SDK说明](https://github.com/Open-CVL/opencvl/blob/4838d1627cf28b28e81d2dd830995fe1fd3a1e2c/README.md)

这使“拍摄点在航片上的位置”具备可检查的监督接口。它不是现成的主动导航数据：尚需检查真实样例的像素尺寸、标签单位、畸变/朝向、父航片足迹与来源分组，不能用简介替代实际文件核验。官方SDK说明完整数据需注册后获取，样例页另有入口；本轮没有提交注册、联系作者或下载数据。第三方依赖/数据条款按各自来源保留。[SDK NOTICE](https://github.com/Open-CVL/opencvl/blob/4838d1627cf28b28e81d2dd830995fe1fd3a1e2c/NOTICE.md)

本轮已新增**评测侧坐标与准入检查器**，不是新Agent：

```text
x = width/2 + dx
y = height/2 - dy
u = x - crop_left
v = y - crop_top
inside = 0 <= u < crop_width and 0 <= v < crop_height
```

该公式只用于检查监督标签，绝不把真实x/y、dx/dy、目标格或答案传入策略。窗口外坐标保留为outside，不能裁到边界后冒充正例；异源不匹配标为unrelated，不生成伪方位。归一化热图不能自动转换成目标存在概率。

三种情形必须分别具备证据：①目标拍摄点在当前观测内；②同源拍摄点在当前窗外；③异源/无可靠对应。第二种情形可有评测侧相对位置标签，但是否从RGB中可辨识、何时应拒绝预测，仍须验证。不能假定所有窗外样本都能被模型正确判断方向。

尺度边界：100m父航片切5×5将是20m/格、总0.01km²，绝不是MassGIS的300m/格扩展。原文偏移主要位于父图中央区域，直接切格还会产生目标位置偏置；不能照抄Masa C4—8分布或宣称覆盖全部25目标格。未来正式确认需要更充分的来源/位置分布，不能用4对工程样例代替。

## 5. 唯一下一批：最多4对的空间监督工程预检草案

本段为下一批条件，**不是当前已执行授权或结果**。

| 项目 | 预定边界 |
|---|---|
| 目标 | 证明照片—航片—拍摄位置的标签可追溯、坐标方向正确、能区分inside/outside/unrelated |
| 素材 | 最多4对官方样例，优先有明确标签来源的ZOD；逐份记录角色与地理/序列分组，不将邻帧当独立区域 |
| 获取上限 | 总≤64MiB，不下载完整数据集；获取前另列精确URL、字节/保留级别和目录授权；不自动注册/提交个人信息 |
| 实现 | 读取原标签、轴向与尺度核对，固定父图/裁窗坐标变换；几何单元检查和输入权限检查；不生成模型预测 |
| 资源 | 0训练、0forward、0导航、0模型API；MM-GAG六确认组继续封存 |
| 必须通过 | 每对文件SHA/标签出处、相机点与父图几何、dx/dy单位、北向与像素轴、来源角色；不含未访问图像的策略接口 |
| 停止条件 | 原始标签缺失/身份不明、无法有界取得、几何冲突、只有中心先验、来源无法分组时保留问题并停止，不凭模型成绩改标签 |
| 通过后 | 再选择一个轻量空间关系模块和真实/禁用/均值/错误目标对照，另冻资源/队列/拒绝门槛；不提前承诺SR或参数规模 |

如果小样例也无法取得或标签不能核实，本路线止于准入，不换成无界爬取/另一个大模型。平台人工地面模式继续可用，航拍主线继续保持；缺陷作为明确适用边界。
