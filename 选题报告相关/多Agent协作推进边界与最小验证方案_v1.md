# 多Agent协作：推进边界与最小验证路线

日期：2026-10-01。研究决策草案，尚未冻结实验协议、实现协作或调用模型。原主方法S2/S3/S4/SwissView验收与默认保持，本文件不是新增方法通过证明。

## 是否继续

建议保留一次有界验证，作为已通过单智能体主线之后的独立支线。原方案曾提出零训练多智能体，当前训练过的探索器与视觉头仍是单智能体的两个模块，不能把已有SR归因于多Agent。如果最终选题仍承诺零训练多智能体，需补真实协作实验并明确整个系统的训练来源；若研究主张调整为目标证据驱动的视觉搜索，多Agent可作为拓展与负结果，不强求超过既有基线。

research.md的持久子目标、跨步关系记忆有参考价值，但本次只隔离独立核验角色，其他机制后续分别验证。当前旋转训练探索收束，现有已见开发用于方法筛选；新方法确认必须另用未见源文件。

## 依据与限制

[DiscussNav](https://arxiv.org/abs/2309.11382)采用不同专长模型参与感知和决策讨论，在R2R导航任务报告收益；可借鉴职责分工，但其指令条件室内任务不等于本项目航拍目标图搜索。

[Scaling Agent Systems v3](https://arxiv.org/abs/2512.08296v3)在标准化工具与计算的多任务对照中发现协作效果依任务结构而异，连续规划可能退步；此结论不提供本项目的SR上限或固定百分比阈值。阅读时以2026-04-08的v3为准，搜索结果中的旧版实验数量不混用。

[MAST v3](https://arxiv.org/abs/2503.13657v3)归纳了系统设计、角色不一致和任务核验等协作失败；可据此增加角色/消息/决策日志，不能推断仅加核验者就会提高SR。本项目路线与以下工程门槛是本地研究判断，不是上述论文的实验结论。

## 最小职责划分

| 角色 | 决策责任 | 保留的独立状态 | 输出 |
|---|---|---|---|
| 探索规划Agent | 在剩余动作预算内提出合法动作及探索理由 | 自己的计划、已访问观察与历史协作消息 | 候选动作、证据引用、可撤回的计划 |
| 目标核验Agent | 判断当前目标实例线索是否支持偏离探索计划，允许未知/弃权 | 自己的支持与反证记录 | 支持/反对/未知、合法动作或弃权、观测引用 |
| 程序协调/执行器 | 按事前规则解决冲突并执行一步 | 公开位置、预算与执行日志 | 最终动作、仲裁原因与环境反馈 |

两个Agent可使用同一冻结VLM的独立上下文，无需两个不同模型或同时驻留GPU。第一轮核验输入不展示规划者本次结论，避免直接附和；程序随后交换消息，角色可在后续决策修正自身状态。规则执行器不是第三个智能体。本项目按独立状态、独立决策、消息交换及反馈修正规定协作的操作定义，不把重复调用同一打分函数改名为多Agent。

各角色仅能读取目标图、当前图、实际已访问历史、公开位置/visited/剩余预算。不能访问邻格图片、未访问特征、完整地图、真实目标坐标或评测器。记忆逐episode清空；两个角色保持同一可用观测集，不用增加图片权限制造协作收益。原环境自动到达即成功、无STOP，核验应服务动作选择，不能套用停步确认收益。

## 有界推进与必要对照

先做少量已见开发任务上的接口/视觉能力诊断，检查结构化输出、核验是否利用目标图、角色是否有实质分歧和消息是否能改变动作。若模型不能可靠利用目标，先结束该协作候选，不扩大Agent数。

通过工程诊断后，才冻结任务与预算进行20题小规模筛选，随后至多一次固定140题开发验证。任务不能只挑已知失败题后称整体SR；原val/test及预留新源图不参与选提示词。以下控制均使用相同图像权限、环境动作预算、模型和执行规则：

1. 原冻结Edge系统：强性能参考。
2. 单Agent单次建议：基本VLM参考。
3. 单Agent两次建议/反思：同调用/计算额度控制。
4. 两Agent提议与独立核验：仅拆分角色状态与协作上下文。

优先把协作限制在公开可判定的“目标线索与探索建议冲突”状态，每题最多2次协作轮，每轮两角色各1请求、无追加辩论；所有LLM对照使用相同触发和调用上限。首版云端执行前要冻结提示、触发、错误/超时处理、最大token/图片数、总请求上限及总费用预算，当前尚未调用。使用同一模型先隔离协作结构，模型能力对照另做。若使用随机云端响应，三轮是API重复，不称三个训练seed，也不增加独立地图数。

## 放行与收束

开发保留的建议门槛：相对同预算单Agent反思平均SR至少+2个百分点、至少2/3配对重复正收益、SG不更差，完整报告源文件SR/SG区间及请求/tokens/图片/时延/失败率。即使超过单VLM，若仍未超过冻结Edge，只能定位为协作机制观察结果，不能替换最佳方案。

要声称目标机制，需另行预登记目标均值/错误目标对照，记录有效纠正与错误否决；只减少误接受或提高覆盖不能当目标理解。所有指标与信息边界、模型/源码/任务/消息/轨迹哈希可追溯。API重复无改善、费用/超时超过冻结预算、或核验损伤正确线索，则本候选结束，保存负结果。开发候选不等于独立泛化，只有冻结配置后的未见源文件确认支持相应新结论。

第一轮不更新参数，可称“无需新增训练的协作层”。如果继续使用本地训练过的Edge/探索器，整个系统不能称零训练；严格零新增任务训练路线需单独使用现成模型与规则并明示预训练来源，其成绩不继承本地训练系统。
