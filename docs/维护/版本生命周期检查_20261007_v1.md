## 建议的长期组织方式

- 当前发布层：根README只突出当前平台、按协议默认、当前材料；平台/README维护一个当前入口和一个历史入口。
- 历史交付层：旧平台启动/说明、小型旧稿和未绑定原件，可在核对引用后归入“历史版本”；迁移先备份、记录旧→新路径/SHA并检查恢复。
- 科研默认层：5×5原M0与Roads10×10径向保护分属不同已验证协议，15×15仍实验性；不能把旧编号的合法默认一并淘汰。
- 科研证据层：实验目录、源使用账本、模型、图块、绑定源码及源码快照原址保持，另用生命周期登记标“历史/失败/已收束/确认”并从当前导航折叠。
- 代码层：先记录current_dependency / historical_reproduction / experimental / superseded_entry / unclassified，不能机械把每个族最高版本当默认。
- 每次版本交付明确本版入口、替代对象、仍保留的功能、回退方式、验收证据；“新增一个_vN”不是完整发布收尾。

## 推荐执行顺序

先修当前导航和状态分层；再给全部版本族建立机器可读登记；最后只迁移已证明无当前依赖且不承载路径绑定的旧交付/草稿。科研原件不动，不整目录清除平台运行记录。最新HANDOFF已有用户上传数据误删事故记录，用户会话不属于可再生测试缓存。

本轮不认定“最新版必然更优或稳定”：V3工程验收沿用PLAT-005的17测试/4步回归记录，未重新执行；旧科研协议优劣仍以各批验收为准。
