## 获得资料后需要提供什么

先由使用者通过[官方自助入口](https://open-cvl.github.io/access.html)取得访问权限，不需要本项目联系论文作者。本轮已核对该公开页面返回200，未填表、未提交注册、未跟随受限档案地址。

不需要先把完整数据集复制进项目。接收最少需要：

- 实际数据根目录和拟选来源的`labels.json`路径；建议使用D盘已有数据位置，新增目录或大下载另行确认。
- 官方档案清单、`SHA256SUMS`以及所选档案的校验/准备回执；本工具不代替官方档案真实性核验。
- **在模型评测前固定**的图像ID清单与拟用角色，首批最多64条；训练准备、开发、确认分开，不把上游train名称当成本项目训练授权。
- 原始来源和划分信息；保留标签来源，修正位姿缺失时不自动退回raw。

当前适配范围为Mapillary普通RGB、明确可用的OpenSfM修正拍摄点。ZOD位姿、全景转照片、校准输入和其它标签约定需要各自适配，不在首版自动兼容范围。

## 新正式资料的入口

工具支持`--labels`加本地数据根、项目角色和预先固定的ID清单；路径需替换为实际资料。下列仅为参数格式，不是已经存在的目录或本轮下载授权：

```powershell
& 'D:\PYTHON\python.exe' -B -m project.src.tools.inspect_capturepoint_intake_v1 --labels 'D:\实际数据根\mapillary\cities\国家\城市\labels.json' --data-root 'D:\实际数据根' --role fit_preparation --select-ids 'D:\实际资料目录\已固定图像ID.json'
```

ID清单为字符串数组，如`["10000258569988630", "1000015350919599"]`，需换成所选来源的真实ID。标签文件上限16MiB、选中记录最多64条、每图最多16MiB、实际哈希读取累计默认64MiB；超限会停止，不静默截断或解压整库。

另一入口是`--manifest`读取已规范化的本地`{"records": [...]}`清单，字段格式可从实测回执的`normalized_records`查看。图像路径相对于`--data-root`，可携带预期SHA256；同一文件命中缓存时也会重新比较调用方提供的预期摘要。没有预期摘要时，只建立本地文件绑定，不能声称已与官方摘要核对。

## 结果怎么解释

| 检查结果 | 意义与处理 |
|---|---|
| `data_preparation_ready=true` | 所选文件、标签字段及角色间隔在本工具范围通过；不是训练、模型准入或正式确认通过 |
| 修正拍摄点在窗外 | 保留为不匹配样本，不夹入目标格、不自动换raw，也不生成可达导航目标 |
| 已消费身份或冻结角色变化 | 拒绝重标新确认/擅自改用途；身份精确命中时在影像读取前拒绝 |
| 同图、同序列、近邻足迹跨角色 | 通过连通分组发现泄漏，报告角色冲突；更名或裁剪不增加独立来源 |
| 文件缺失、哈希/头异常、路径歧义 | 报错并保留失败行，不静默跳过或选择另一个相似文件 |

预检只读PNG/JPEG编码头和文件SHA，不解码像素、不做模型编码，也不验证图像视觉质量、绝对拍摄点精度或校准链。地理隔离基于数据集坐标和尺度；新确认检查仅覆盖传入的已消费账本，目前绑定CV-042的9来源，不覆盖预训练模型的未知地理经历或全项目所有来源。

报告中的拍摄点、路径、身份与角色只供数据整理/监督/评测，**不能直接作为Agent输入**。所有输出都保持`training_authorized=false`和`formal_confirmation_admitted=false`；新增真实数据仍须冻结资源、来源用途、目标对照及确认协议。
