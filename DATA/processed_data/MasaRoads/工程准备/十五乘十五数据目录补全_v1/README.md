# DATA-001：15×15连续区域目录与地理标签调查

本批只调查公开元数据和有限文件头，无完整影像下载、像素解码、训练、导航或新SR。方案见[执行协议](执行协议.md)，资源、源码和旧输入见[预登记](预登记.json)。原151足迹及已消费24区域只读排除，旧默认与历史验收不改。

## 接手入口

1. 先读仓库AGENTS、TASKS及HANDOFF，重新认领已释放或明确移交的具体范围。不要停止其它执行者进程。
2. 在根目录用现有Python运行`project/src/data/area_catalog_v1.py run`。它先校验冻结源码/输入，复用保存的HTML和头文件；开始但中断的请求仍占尝试。不要改冻源码、删请求日志或重复建同名批次。
3. 若`目录分析结果.json`已经存在，不再重跑抓取；运行`project/src/eval/audit_area_catalog_v1.py`进行独立方程复核。复核输出若已存在先读取，不能覆盖。
4. 最终调查依据为目录分析结果、调查输出封存、核验/独立复核，以及后续独立调查报告。没有报告/复核时不把目录候选称合格数据，不称调查完成。

## 文件职责

- `元数据/官方_*.html`：作者公开页面与六个航拍目录原文。
- `元数据/合并目录.json`：集合、上游分区、URL及文件名去重提案，跨URL的像素相同未确认。
- `元数据/文件头队列.json`、`元数据/GeoTIFF头/`：固定队列、最多64KiB文件头、GeoTIFF地理标签判定；新影像的像素质量未知。
- `元数据/请求记录.jsonl`：URL尝试、实际读入正文量、HTTP状态、响应绑定及错误；先开始再计入尝试。
- `源码快照/`：本批冻结源码，不因后续开发更新。

Roads全部分区是主池；Buildings是同作者RGB候选来源扩展，单列容量及边界，不能自动沿用旧Roads验收结论。实际坐标检查不替代完整影像质量和空间连续性工程；正式导航前另冻数据/任务协议。
